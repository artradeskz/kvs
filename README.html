НАЗНАЧЕНИЕ И КОНЦЕПЦИЯ

КВС — это ассемблер для архитектуры x86-64, полностью использующий русскую лексику для мнемоник инструкций, имён регистров и директив. Проект носит образовательный и экспериментальный характер и демонстрирует принципы работы ассемблера, построения ELF-файлов и трансляции высокоуровневых концепций в машинный код.

Ключевые принципы проекта:
  • Русскоязычный синтаксис — все инструкции, регистры и директивы на кириллице
  • Модульная архитектура — лексер, парсер, два прохода, сборщик ELF
  • Минимализм зависимостей — только стандартная библиотека Python
  • Подготовка к самокомпиляции — архитектура, допускающая написание компилятора на самом КВС

ОСОБЕННОСТИ И ВОЗМОЖНОСТИ

  • Полностью русский синтаксис — переместить, прибавить, вызвать, регистры раикс, есипи, ал, директивы .текст, .данные, .бсс
  • Генерация исполняемых ELF-файлов — 64-битные ELF для Linux, готовые к запуску
  • Двухпроходная сборка — традиционная схема с разрешением меток
  • Поддержка секций — разделение на .текст (код), .данные (инициализированные данные) и .бсс (неинициализированные данные)
  • Полная адресация памяти:
    • Абсолютная адресация по меткам [переменная]
    • Абсолютная адресация по числовому адресу [0x402000]
    • Косвенная адресация через регистр [раикс]
    • Всё с RIP-relative кодированием для 64-битных перемещений
  • CSV-логирование — детальный файл .csv с соответствием адресов, байтов и исходных команд
  • Более 50 инструкций — полный набор основных команд x86-64
  • Рефакторинг — кодогенерация вынесена в отдельный модуль kvs_pass2_encoder.py

АРХИТЕКТУРА И ПРОЦЕСС СБОРКИ

УСТАНОВКА И ЗАПУСК

# Клонирование репозитория

cd kvs

# Установка прав на выполнение (при необходимости)

# Запуск скомпилированной программы

СИНТАКСИС ИСХОДНЫХ ФАЙЛОВ (.квс)

; Комментарий начинается с точки с запятой

.бсс                        ; Начало секции неинициализированных данных
    счётчик: .байт 0        ; Переменная без начального значения

.данные                     ; Начало секции инициализированных данных
    message: .строка_нуль "Привет, мир!"

.текст                      ; Начало секции кода
.глобал _start              ; Точка входа

_start:
    ; Абсолютная адресация через метку
    переместить_имм раикс, 42
    сохранить [счётчик], раикс    ; запись в BSS-переменную
    
    ; Абсолютная адресация через число
    сохранить [0x402000], раикс   ; запись по абсолютному адресу
    
    ; Косвенная адресация через регистр
    переместить_имм рбикс, message
    загрузить раикс, [рбикс]      ; чтение через регистр

    ; Системный вызов write
    переместить_имм раикс, 1
    переместить_имм рсиай, message
    переместить_имм рдикс, 13
    вызов_системы

    ; Выход с кодом из счётчика
    загрузить рдиай, [счётчик]
    переместить_имм раикс, 60
    вызов_системы

РАБОТА С ПАМЯТЬЮ

✓ РЕАЛИЗОВАНО (v2.0): Абсолютная адресация (метки и числа), косвенная адресация через регистры

Поддерживаемые формы:

СинтаксисОписаниеПример
[метка]Адрес метки (из .данные или .бсс)загрузить раикс, [переменная]
[число]Абсолютный адрессохранить [0x402000], раикс
[регистр]Косвенная адресация через регистрзагрузить раикс, [рбикс]

Пример использования:

.бсс
счётчик: .байт 0
указатель: .байт 0

.данные
переменная: .байт 42
message: .строка_нуль "Hello"

.текст
_start:
    ; Абсолютная адресация через метку
    загрузить раикс, [переменная]
    
    ; Абсолютная адресация через число
    сохранить [0x402000], раикс
    
    ; Косвенная адресация
    переместить_имм рбикс, переменная
    загрузить раикс, [рбикс]
    
    ; Работа с BSS
    сохранить [счётчик], раикс
    
    ; Завершение
    переместить_имм раикс, 60
    загрузить рдиай, [счётчик]
    вызов_системы
📌 ВАЖНО: Все тесты из папки тесты/ успешно собираются и запускаются, включая тест, воспроизводящий баг с BSS-секцией. Адресация работает корректно во всех формах.

ПРОЦЕСС ТРАНСЛЯЦИИ И ВЫХОДНЫЕ ФАЙЛЫ

Запуск ассемблера:

python3 kvs_build.py программа.квс

В результате создаются файлы:

  • программа.токены — результат лексического анализа
  • программа.аст — AST-представление
  • программа.проход1 — результаты первого прохода (размеры, метки)
  • программа.csv — детальный лог с адресами, байтами и командами
  • программа.elf — исполняемый ELF-файл

СТАТУС РЕАЛИЗАЦИИ

✅ Полностью реализовано (v2.0)

  • Лексер с токенами [, ], NUMBER
  • Парсер с поддержкой операндов в квадратных скобках
  • Первый проход с корректным расчётом размера инструкций с памятью
  • Второй проход с кодированием адресации через RIP-relative
  • Абсолютная адресация по меткам [переменная]
  • Абсолютная адресация по числовым адресам [0x402000]
  • Косвенная адресация через регистры [раикс]
  • Секция .бсс для неинициализированных данных
  • Рефакторинг: выделение кодировщика в отдельный модуль
  • Более 50 инструкций x86-64
  • CSV-логирование

⚠️ Частично реализовано / ограничено

  • загрузить_адрес (LEA) — только для чисел, не для меток
  • Старшие 8-битные регистры (AH, BH, CH, DH) не поддерживаются
  • Регистры R8–R15 не поддерживаются

ПЛАН РАЗВИТИЯ

v2.0 (текущая) — Адресация и BSS

  • ✅ Лексер: [, ], NUMBER
  • ✅ Парсер: [метка], [число], [регистр]
  • ✅ Pass1: корректный расчёт размера инструкций
  • ✅ Pass2: RIP-relative кодирование
  • ✅ Абсолютная адресация (метки и числа)
  • ✅ Косвенная адресация ([reg])
  • ✅ Секция .бсс
  • ✅ Рефакторинг энкодера

v3.0 (планируется) — Расширенная адресация

  • ❌ [reg + disp] — адресация со смещением
  • ❌ [reg + reg*scale] — с индексным регистром
  • ❌ [reg + reg*scale + disp] — полная SIB-адресация
  • ❌ LEA для меток
  • ❌ PUSH/POP/CALL/RET

v4.0 (отложено) — Стандартная библиотека

  • ❌ malloc, free
  • ❌ strlen, strcmp, memcpy
  • ❌ putchar, getchar

ОГРАНИЧЕНИЯ

  • Адресация со смещением — формы [reg+disp], [reg+reg*scale], [reg+reg*scale+disp] не реализованы
  • LEA для меток — загрузить_адрес reg, [метка] не работает, используйте переместить_имм reg, метка
  • Старшие 8-битные регистры — AH, BH, CH, DH не поддерживаются
  • Расширенные регистры — SPL, BPL, SIL, DIL, а также R8–R15 не поддерживаются
  • Нет умножения и деления — инструкции MUL/DIV не реализованы
  • Нет операций со стеком — PUSH/POP/CALL/RET отсутствуют
  • Нет динамической памяти — нет встроенных malloc/free
  • Нет макросов и условной компиляции
  • Экспериментальный статус — некоторые инструкции могут быть реализованы не полностью
