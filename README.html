НАЗНАЧЕНИЕ И КОНЦЕПЦИЯ

КВС — это ассемблер для архитектуры x86-64, полностью использующий русскую лексику для мнемоник инструкций, имён регистров и директив. Проект носит образовательный и экспериментальный характер и демонстрирует принципы работы ассемблера, построения ELF-файлов и трансляции высокоуровневых концепций в машинный код.

Ключевые принципы проекта:
  • Русскоязычный синтаксис — все инструкции, регистры и директивы на кириллице
  • Модульная архитектура — лексер, парсер, два прохода, сборщик ELF
  • Минимализм зависимостей — только стандартная библиотека Python
  • Подготовка к самокомпиляции — архитектура, допускающая написание компилятора на самом КВС

ОСОБЕННОСТИ И ВОЗМОЖНОСТИ

  • Полностью русский синтаксис — переместить, прибавить, вызвать, регистры раикс, есипи, ал, директивы .текст, .данные
  • Генерация исполняемых ELF-файлов — 64-битные ELF для Linux, готовые к запуску
  • Двухпроходная сборка — традиционная схема с разрешением меток
  • Поддержка секций — разделение на .текст (код) и .данные (данные)
  • Абсолютная адресация памяти — чтение и запись по меткам [переменная] и абсолютным адресам [0x402000] с RIP-relative кодированием
  • CSV-логирование — детальный файл .csv с соответствием адресов, байтов и исходных команд
  • Более 50 инструкций — полный набор основных команд x86-64
  • Рефакторинг — кодогенерация вынесена в отдельный модуль kvs_pass2_encoder.py

АРХИТЕКТУРА И ПРОЦЕСС СБОРКИ

УСТАНОВКА И ЗАПУСК

# Клонирование репозитория

; Комментарий начинается с точки с запятой

    message: .строка_нуль "Привет, мир!"

.текст                      ; Начало секции кода
.глобал _start              ; Точка входа

_start:
    ; Работа с памятью
    переместить_имм раикс, 42
    сохранить [переменная], раикс    ; запись в память
    
    загрузить рбикс, [переменная]    ; чтение из памяти

    ; Системный вызов write
    переместить_имм раикс, 1
    загрузить_адрес рсиай, message
    переместить_имм рдикс, 13
    вызов_системы

    ; Выход с кодом из переменной
    переместить_имм раикс, 60
    загрузить рдиай, [переменная]
    вызов_системы

РАБОТА С ПАМЯТЬЮ

✓ РЕАЛИЗОВАНО (v2.0): Абсолютная адресация через метки и числа

Поддерживаемые формы:

СинтаксисОписаниеПример
[метка]Адрес метки (из .данные)загрузить раикс, [переменная]
[число]Абсолютный адрессохранить [0x402000], раикс

Пример использования:

.данные
переменная: .байт 0
результат: .байт 0

.текст
_start:
    ; Запись значения
    переместить_имм раикс, 42
    сохранить [переменная], раикс
    
    ; Чтение значения
    загрузить рбикс, [переменная]
    
    ; Завершение с кодом 42
    переместить_имм раикс, 60
    загрузить рдиай, [переменная]
    вызов_системы
⚠️ ВАЖНО: Порядок объявления в секции .данные имеет значение! Переменные, объявленные перед строковыми константами, могут затереть первые байты строк. Рекомендуется объявлять строки первыми, а изменяемые переменные — после.

ПРОЦЕСС ТРАНСЛЯЦИИ И ВЫХОДНЫЕ ФАЙЛЫ

Запуск ассемблера:

python3 kvs_build.py программа.квс

В результате создаются файлы:

  • программа.токены — результат лексического анализа
  • программа.аст — AST-представление
  • программа.проход1 — результаты первого прохода (размеры, метки)
  • программа.csv — детальный лог с адресами, байтами и командами
  • программа.elf — исполняемый ELF-файл

СТАТУС РЕАЛИЗАЦИИ

✅ Полностью реализовано (v2.0)

  • Лексер с токенами [, ], NUMBER
  • Парсер с поддержкой операндов в квадратных скобках
  • Первый проход с корректным расчётом размера инструкций с памятью
  • Второй проход с кодированием абсолютной адресации через RIP-relative
  • Поддержка меток в операндах памяти [переменная]
  • Рефакторинг: выделение кодировщика в отдельный модуль kvs_pass2_encoder.py
  • Более 50 инструкций x86-64
  • CSV-логирование

⚠️ Частично реализовано

  • загрузить_адрес (LEA) — только для чисел, не для меток
  • Сложные выражения в операндах памяти парсятся, но не кодируются

❌ В разработке (v3.0)

  • Косвенная адресация [reg]
  • Адресация со смещением [reg + disp]
  • Сложная адресация с индексом [reg + reg*scale]
  • Полная SIB-адресация [reg + reg*scale + disp]
  • Директива .bss для неинициализированных данных
  • LEA для меток (загрузить_адрес reg, [метка])
  • Стандартная библиотека

ПЛАН РАЗВИТИЯ

v2.0 (текущая) — Абсолютная адресация

  • ✅ Лексер: [, ], NUMBER
  • ✅ Парсер: [метка] и [число]
  • ✅ Pass1: размер = 7 байт
  • ✅ Pass2: RIP-relative кодирование
  • ✅ Поддержка меток в памяти
  • ✅ Рефакторинг энкодера

v3.0 (планируется) — Косвенная и относительная адресация

  • ❌ [reg] — косвенная адресация через регистр
  • ❌ [reg + disp] — со смещением (disp8/disp32)
  • ❌ [reg + reg*scale] — с индексным регистром
  • ❌ [reg + reg*scale + disp] — полная SIB-адресация
  • ❌ .bss — секция неинициализированных данных
  • ❌ LEA для меток

v4.0 (отложено) — Стандартная библиотека

  • ❌ malloc, free
  • ❌ strlen, strcmp, memcpy
  • ❌ putchar, getchar
  • ❌ printf (упрощённый вариант)
Зависимости между подзадачами: Лексер (шаг 1) ✅ ↓ Парсер (шаг 2) ✅ ↓ Данные инструкций (шаг 3) ⚠️ ↓ Pass1 (шаг 4) ✅ ↓ Pass2 (шаг 5): ⚠️ ЧАСТИЧНО 5.1 → 5.2 → 5.3 → 5.4 → 5.5 ↓ 5.6 (генераторы инструкций) ↓ 5.7 (диспетчер) ✅ ↓ Тестирование (шаг 6) ⚠️ ЧАСТИЧНО ↓ Библиотека (шаг 7) ❌ ОТЛОЖЕНО

ОГРАНИЧЕНИЯ

  • Косвенная адресация памяти — поддерживается только абсолютная форма [метка]; адресация через регистры [reg] в разработке
  • Сложная адресация — формы [reg+disp], [reg+reg*scale], [reg+reg*scale+disp] не реализованы
  • LEA для меток — загрузить_адрес reg, [метка] не работает, используйте переместить_имм reg, метка
  • Отсутствие .bss — все переменные инициализируются и попадают в .data (занимают место в файле)
  • Нет динамической памяти — нет встроенных malloc/free (можно реализовать через syscall brk)
  • Нет макросов и условной компиляции
  • Экспериментальный статус — некоторые инструкции могут быть реализованы не полностью
